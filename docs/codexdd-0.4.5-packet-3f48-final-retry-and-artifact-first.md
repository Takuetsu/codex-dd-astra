# CodexDD 0.4.5 — 3F.48, artifact-first optimized Windows retry

## Historical failure and the real success to preserve

[3F.47 run #40884725763](https://github.com/Takuetsu/codex-dd-astra/actions/runs/40884725763) is **RED**, despite the optimized `//codex-rs/cli:release_files` target actually succeeding with **2,858 actions, 794 internal, 2,064 local**, elapsed **9,890.717 seconds** and both real `codex.exe` and `codex.pdb` outputs. The script incorrectly treated the absence of Bazel disk-cache hits as a failed build. The upstream `release_binary` transition adds `cargo-release-profile` and exec-profile flags, which can invalidate direct-core Bazel cache action keys despite successful restoration. **No CLI/PDB artifacts from that terminated GitHub runner were retained**; the combined package did not start. The historic run must remain RED.

## Resolved source code and new bounded run

- `codexdd-045-staged-optimized-windows.ps1` now reports missing CLI/combined cache hits as a **warning**. It still requires actual Bazel target completion, release opt/thin-LTO, physical EXE/PDB, PDB/PE signatures and source SHA pins.
- `codexdd-045-preserve-real-cli-pdb.ps1` independently parses **real successful Bazel target receipts**, verifies the two physical files' PE and MSVC PDB magic signatures and nontrivial sizes, copies them into the nonrelease artifact directory and records their SHA-256. It executes even if a later stage condition fails. If actual CLI compilation was incomplete, it refuses to report files.
- [`3F.48 source-frozen workflow`](https://github.com/Takuetsu/codex-dd-astra/blob/dd/codexdd-v0.4.5-109-overlap-semantic-review/.github/workflows/codexdd-045-3f48-optimized-cli-and-combined-retry.yml) restores **the previous successful core snapshot** `codexdd045-3f47-40884725763-core-complete`; **does not repeat the 44-minute seed or 9-minute core-finish jobs**. It has a 358-minute GitHub-hosted hard bound, 195-minute CLI soft cap, 145-minute combined archive soft cap. It uploads **actual unsigned CLI/PDB immediately** after successful native compilation, **before** the combined archive. The combined job reuses the same Windows runner and Bazel output base, checks all five PE executables and five matching MSVC PDBs, writes SHA-256 inventory, and uploads the actual combined archive separately. Both uploads are nonrelease and short-retention.
- The workflow is initially protected by `NOT_ARMED_FOR_045_OPTIMIZED_RELEASE` one-shot guard. A cheap Linux source/PowerShell preflight must first pass; an explicit parent-SHA arming edit then launches exactly one Windows run. No automatic reruns, production signing/installing, or version promotion.

**Residual risk:** The transitioned CLI's prior 2h45m long link will need recompilation because the first run did not save either its compiled output or action cache. If other combined binaries need longer than their budget, the CLI/PDB will still remain in GitHub artifacts for a subsequent targeted package strategy; do not discard them. A source-frozen artifact build does not approve the 109 overlapping path owners, direct WSL/daemon lifecycle, or final Daniel-CL 21-stage suite. Production remains CodexDD 0.4.4.
