## Security and review implications

1. **Windows daemon privilege:** The fork-specific typed denial and extra token-size check in `windows.rs` replace a generic upstream error. Two surrounding daemon/CLI files are additive or upstream exact. Hosted Windows compile/unit checks do not establish actual elevated SSH F2 or detached daemon lifetime. The upstream `daemon_startup.rs` test's early-return on non-elevated runners is **inherited upstream**, not evidence of fork-origin test suppression.
2. **CLI adaptive-family override:** The only delta in `cli/src/main.rs` is root/subcommand merge of the optional `--adaptive FAMILY` parameter. Source semantics are plausible, but current reviewed CLI tests cover analogous `--no-daemon` and `--no-alt-screen` precedence, not this exact optional adaptive precedence. Capture a focused Windows CLI test or real resume/fork invocation at the proper gate; do not confuse parsing with authenticated Worker-role binding.
3. **Core trusted execution:** The `agent_websocket.rs` and `unified_exec.rs` deltas add tests for nested execution output/evidence ID; `scenarios.rs` only drops an import. Existing core trust/authorization implementations must still be judged separately; test metadata alone never authorizes a Worker to mutate `WorkflowState`.
4. **External-session authority:** `append.rs` is one of the three mixed diffs. It now refuses imported-source `WorkflowState` while preserving legitimate destination history during exact transcript-prefix comparison; the **Daniel-CL 3/3 append unit test** passed. See [source patch and test boundary](codexdd-0.4.3-packet-3f-import-workflow-authority.md). The untrusted external JSONL parser itself reconstructs text-only rollout source; no exploit through its current parser is asserted.
5. **Rollout trace/privacy:** The trace adapter's only CodexDD delta is explicit **non-tracing** of `AdaptiveRuntimeSignal` as a tool or wrapped protocol event. Borrowed command/MCP event serialization is substantially upstream behavior and was not newly introduced by the fork. Its existing storage/access/redaction policy still deserves a release-security review; **do not claim either a new leak or proven sanitization from this diff**.
6. **Generated SDK:** Python signal/registry model additions are an additive generated output. The prior [13-artifact exact generator drift check](https://github.com/Takuetsu/codex-dd-astra/actions/runs/38157430174) passed on an earlier source snapshot; source trees and future candidate receipts need their own pinned reproducibility attestations.
