# CodexDD 0.4.5 — 3F.48: protect actual optimized CLI success from cache-efficiency false failure

**Historical native result:** [3F.47 Windows run #40884725763](https://github.com/Takuetsu/codex-dd-astra/actions/runs/40884725763) has a **RED** final job but a **real fully successful optimized CLI/PDB Bazel target**. Exact source `f5649dba2d8cfa172d248e6ada9696ced51e8b8e`. `core_seed` and `core_finish` were GREEN; the latter reused **1,625 real cached actions**. The final runner restored the prior exact **1.164GB compressed complete-core action cache** but the transitioned CLI release target reported **2,858 total actions, 794 internal, 2,064 local, 0 disk-cache hits**. It took **9,890.717 seconds** and reached `Build completed successfully`, with actual `codex.exe` and `codex.pdb` paths printed by Bazel. Then the staging PowerShell script threw `No real compiler action cache reuse in cli` BEFORE inspecting or retaining either binary. Thus all binary upload steps were skipped and the finished CLI/PDB bytes were lost with the ephemeral hosted runner; the combined archive never started. This was an invalid **cache efficiency** acceptance condition, not an optimized Rust compiler error or missing PDB.

The upstream `release_binary()` rule applies a `_release_profile` transition that adds the `cargo-release-profile` features to dependency configurations and extra release exec flags. The core warm target built directly does **not** necessarily share its action keys with the transitively transitioned CLI target. A restored cache key **is not proof of reusable action objects across configurations**. 3F.48 makes no source or optimization changes: actual build completion, pinned release flags, real physical EXE/PDB content, all archive member validations remain mandatory. Disk-cache zero hits at the CLI/combined target are now **diagnostic warnings**, never grounds to reject successful built binaries. Distinct exact cache hit conditions remain mandatory at explicit cross-runner checkpoint stages, where they are meaningful.

**Prevent lost artifacts next:** source-frozen final-only retry must upload actual CLI EXE/PDB *immediately after* the CLI stage, even if combined package compilation fails. It must reserve sufficient margin beyond the observed 164m51s CLI link and must not repeat core seed/finish, which have already been cached and green. The old hosted runner has terminated, so the finished CLI/PDB cannot be recovered from its GitHub diagnostics artifact. The combined package remains unbuilt. PR #58 stays draft and production 0.4.4 unchanged.
