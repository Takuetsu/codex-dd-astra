# CodexDD 0.4.5 — 3F.45: fix false-negative Bazel disk-cache argument verification

**NONRELEASE; production Rust source unchanged.** [3F.44 #40787409455](https://github.com/Takuetsu/codex-dd-astra/actions/runs/40787409455) passed the 109-owner/source guard and preinstalled MSVC/locked Bazel setup. Its 10-minute optimized Rust seed reached **[1,008 / 1,320] actions** before its expected checkpoint timeout, but then failed at `codexdd-045-3f44-checkpointed-opt-cache.ps1:61`: `Missing optimized flag: --disk_cache=D:/_bazel-disk`.

The flag was already included in the executed Bazel argument array. Bazel's `--announce_rc` prints inherited/configured flags but not necessarily arbitrary direct CLI arguments, so searching combined stdout/stderr for the exact direct `--disk_cache` flag was invalid. This failure occurred before cache inventory, saved checkpoint and second-runner restore, and **does not prove a Rust compilation error or inadequate cache size**.

The 3F.45 change validates the explicit flag by exact membership and ordering in the **actual PowerShell argument array**, after `--config=ci-windows-msvc`, ensuring it overrides `.bazelrc`'s `common:ci --disk_cache=`. Keep the log verification for `--compilation_mode=opt` and thin LTO, which are actually printed by `--announce_rc`. Move the on-disk `D:/_bazel-disk` byte/file inventory before optional log-string assertions, so any future failure reports cache size and the configured cap. A separate source-only audit includes a representative captured-log fixture that deliberately lacks the direct CLI flag but retains the real release flags. No optimization/security/dependency or actual build flags changed.

The new Windows validation will be the same bounded 10-minute seed and up-to-22-minute resumed target, with exact GitHub action-cache transport and normalized MSVC PATH checks. The first seed's timeout is checkpoint success **only if completed action outputs are present within bounds**; the second runner must actually finish the same Rust target and prove cache hits. 3F.43 full optimized CLI/PDB/combined workflow remains dormant, 109-owner signoffs and final 21-stage Daniel-CL suite remain pending, production stays 0.4.4.
