# 3F.45C — Protect dormant optimized CLI/PDB + archive from Bazel flag log false negatives

**NONRELEASE; source-only.** After [3F.44 Windows #40787409455](https://github.com/Takuetsu/codex-dd-astra/actions/runs/40787409455) failed on a `--disk_cache` log assertion, inspection found the same invalid assumption in the **dormant** `codexdd-045-staged-optimized-windows.ps1` executor. A long warm/core/CLI/combined release stage could therefore have compiled successfully yet been rejected by searching Bazel's `--announce_rc` output for a directly supplied CLI option.

3F.45C corrects that verification before activation: the staged executable builds and checks the actual `--disk_cache=D:/_bazel-disk` command argument, exactly once and positioned after the `--config=ci-windows-msvc` config that disables disk caching by default. The log receipt still validates actual success, optimization and thin LTO. This changes neither the build flags nor actual Rust sources. Source-only tests assert the fix and preserve the `NOT_ARMED_FOR_045_OPTIMIZED_RELEASE` sentinel, locked Cargo/deny sources, pending 109-owner signoffs and production 0.4.4.

**Follow-up**: [3F.45B Windows checkpoint proof #40877812353](https://github.com/Takuetsu/codex-dd-astra/actions/runs/40877812353) is separately testing partial cache saving and exact restore with a bounded medium real Rust crate. Even if that succeeds, full CLI/PDB/combined archive remains unbuilt and must not be enabled without further capacity review and explicit approval. No release/installer/merge or Daniel-CL work is triggered.
